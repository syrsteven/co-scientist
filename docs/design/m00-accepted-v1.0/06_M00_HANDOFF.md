## 1. 一段话项目目标

为内部医学／生物学科研人员重新构建**单一、科学能力优先**的 Co-Scientist：研究问题和背景文献 → 生成明确可验证的完整假说 → 候选伦理与分层科学核查（R0、R1、R2；R2普通证据缺口返回M03–M06后再汇总；R2高影响风险进入R3再回R2）→ 依据固定的候选准入 → 成对Ranking／TrueSkill → 合格父代UCB选择及Crossover／Mutation → 独立复审子代 → 最高合格μ的终局或明确无Winner；后续M18独立实验前核验与M19实验规划。源码参考 Nature/arXiv论文与旧G3，但系统重建而非扩张G3，旧G3仅做独立科学对照。

## 2. 各新聊天必须视为已定的跨模块规则

1. **单一新系统。** 旧G3不再是正式运行分支；不要求旧Run恢复、schema兼容、旧Controller/旧软件测试套件全部通过。
2. **R1属于Reflection。** M03 Inventory/Coverage、M04 Retrieval、M05 Evidence Appraisal、M06 Prior-art/Dossier；M07是完整机制整体评议责任人。
3. **R2有两种不同的入场前科学返回路径。** 新必要前提、Coverage遗漏或普通证据缺口由R2提出M03–M06补核查请求，更新Dossier再返回R2；高影响科学Issue才触发R3，所有R3结果（包括无新材料）都返回R2。R3不能改假说、自动生成子代或直接准入。
4. **Ranking绝不反向执行科研核查。** 同一候选跨Match的核心科学呈现必须一致（主要支持、重要反证、关键缺口、最终Reflection）；仅允许从冻结材料按统一对称策略增补，并记录模型实际输入。`needs_more_evidence`是非决定性比较理由和未来研究反馈，不向M03–M08发任务；非决定性不更新μσ。
5. **正常Run只有一个连续Epoch；不同Generation候选追加入场。** 一旦候选参赛，其科学内容、Dossier、最终Reflection和固定输入引用不得变化；不实现常规Epoch重建/Match失效/评分迁移。
6. **子代独立科学审查。** M11产生新Hypothesis和DeltaProposal；Ethics/R0后M03形成Inventory/ResolvedDelta，再由M04/M05做条件复用，M06生成新Dossier、M07进行完整R2。子代不继承父代评分。
7. **仅合格父代繁殖。** 未准入/不具父代资格不得加入UCB父代池；第一版没有自动修复未准入候选的Mutation入口。
8. **正式终局最高合格TrueSkill μ。** UCB只用于父代探索；终局不再加R3；M10定义终局资格，资格不足可以没有Winner。
9. **完整必要Claim Coverage。** 不固定数量上限；检索/评价范围完整、无阻断且可检验但无直接证据仍可准入。技术失败、科学未知、冲突、科学阻断各自有独立语义。
10. **资源只记录，不给用户设置总预算。** 保留单次API/工具技术边界、真实调用/用量记录和必要幂等恢复。
11. **科学能力评测前置。** 代码正确不等于科学正确；M20a用固定专家案例先开始。
12. **HITL暂缓；M18/M19是独立后续阶段。** 工作区、实验核验不得回写或重新排名旧Ideation Run。

## 3. 已随设计整包验收的最小交接做法

- `FinalReflection` 作为M07整体输出，引用R0、Dossier、必要R3；`Admission`作为M09轻量的固定参赛引用清单。没有必须新增的Reflection Bundle/Evaluation Basis服务。
- 模型调用记录保存真实可见Evidence View、摘要与裁剪、文献访问层级和调用输入；不再单独建立一个科学评价对象。
- `DeltaProposal`与`ResolvedDelta`分离；M03拥有真实Inventory后的变化解析，M04/M05拥有证据适用性与复用判断。
- R3通过明确Issue/范围/结果记录阻止同问题无限重查；核查执行未完成不能被当科学完成；不规定任意“最多三次R3”。
- M09a/M11a/M14a/M15a/M20a只先给出最小接口、固定样例及执行能力，非新增模块和全平台前置。
- M01与M04共享窄文献检索能力，但分别负责背景与主张导向检索；M13为可选非阻断科研增强。

**注意：** 上述已随Phase 3 RC2整包验收成为设计约束；具体schema/类名与实施方式仍由拥有模块决定。**不能把它解释成已完成Pydantic实现。**

## 5. 一次新模块聊天应附哪些输入

**必须附：** (a) 本已验收 `M00_Phase3_Accepted_v1.0` 包的 `01/02/03/04/06` 文件，或完整ZIP；(b) 该模块最新的已验收上游 Handoff 与实际代码/配置 SHA；(c) 该模块真实数据、专家样例及旧代码移植候选（若相关）；(d) 模块自己的待定科学问题。

**新聊天起始步骤：**

1. 重新核实 GitHub 最新 main 与该模块实际调用链；不可把M00的2026-10-31 SHA自动当未来当前HEAD。
2. 读取本包后标出与任何新accepted上游契约的冲突；明确哪些本模块需要的科学阈值尚未决定。
3. 设计时先输出本模块核心科学问题、方法、评测和最小必要接口；不向上游默默提出超过M00边界的修改。
4. 科学设计得到用户批准之前不得实施生产代码；实现后必须记录真实测试、专家评测、失败、用量、文件及commit。
5. 产出正式模块Handoff供下一个聊天，不依赖继续记住本轮对话。

**可直接复制到下一聊天的系统级约束：**

> 本项目是单一全新Co-Scientist科学系统，不扩张G3；M00-ARCH-v1.0 已于2026-11-01完成设计验收。Goal运行时先 M01.prepare_goal→M02.screen_goal→M01.generate_hypotheses→M02.candidate_ethics/R0；候选R1(M03–M06)→R2。R2识别普通必要前提/Coverage/证据缺口时，可请求M03–M06补查后返回R2；只有高影响风险由R2触发R3并回R2。Admission固定科学依据→Ranking只比较，跨Match保留相同候选核心支持/反证/缺口/FinalReflection，对称增补冻结材料并记录真实输入；TrueSkill非决定性不更新且不触发新核查→UCB只选合格父代→Crossover/Mutation→新子代完整复审。正常Run一个Epoch，终局最高合格μ，不加额外R3，资格不足可无Winner。M13可选使用M03/M06/M07/M10/M11数据但不阻断。无用户总资源预算，仅记账。Claim不设固定数量上限。M18/M19独立，HITL另题。具体科学阈值由模块和M20评测决定；M00设计验收不等于批准任何生产代码。
