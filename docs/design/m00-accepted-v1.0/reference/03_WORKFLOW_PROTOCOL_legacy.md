# 单个聊天的工作协议

## 开始：证据确认

1. 阅读 `00_COMMON_CONTEXT.md` 与当前模块说明；读取相关 accepted Handoff。
2. 核对 GitHub 最新 main、工作树和本模块源码真实调用链；标明论文原文披露 vs 本地代码 vs 新方案。
3. 输出当前模块 As-Is → To-Be、职责边界、关键状态/接口、待定科学规则。

## 1：设计门（用户批准之前）

- 提供信息密度高的技术设计与关键取舍；标识 [已定] [拟议] [待定]。
- 不因有旧 V2 Schema 就推定 目前G3版本 在使用；不因模型引用可追溯就推定科学判断正确。
- 输出拟议文件清单、契约/事件版本、回归测试和科学评测要求。
- **未经用户明确批准，不让 Codex 开始正式修改。**

## 2：实施与验收

- Codex 在独立分支实现批准范围，生产数据/冻结 G3 不改。
- 运行离线测试和相关科学样例验证；记录准确命令、跳过项、失败和环境信息。
- 如需变更已批准接口，先回到 1；不在 commit 里偷偷扩展范围。

## 3：交接

- 完整填 `01_HANDOFF_TEMPLATE.md`，同步 `02_PROJECT_STATE.md` 与变更决策日志；留下可引用的固定文件和 commit。
- 下一模块只接收 accepted 接口版本。未经实施的设计只标 `proposed`。
- 跨模块故障归属对应模块，而不是在当前任务里无边界修复。
