# Co-Scientist W0｜科学与接口验收样例（设计草案）

**版本：** `W0-M20a-CASES-v0.1 / proposed`  
**上游：** `M00-ARCH-v1.0 / design_accepted`；配套 `01_W0_MINIMAL_INTERFACES_PROPOSED.md`。  
**材料属性：** 下列所有病例、文献卡片、模型输出和数值均为**合成测试情境**，不是来自真实论文或专家标注的科学结论；其“预期”只验证明确的流程规则。**不能将这些样例作为证明系统科学质量的 benchmark。**

## 1. 评价层次：不能混淆

| 层次 | 当前可以准备的依据 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **A. 合成接口/不变量样例** | M00已定规则 + 本文件人为设置的输入/响应 | 调用方向、信息固定、身份与权限、重试/评分状态是否正确 | 生物医学假说是否真实、文献解读是否正确、候选是否创新 |
| **B. 真实科研专家样例** | 未来封存的真实研究问题、原始文献、专家独立标注 | Claim覆盖、证据归因/适用性、整体机制评价、排序质量 | 不能仅靠合成样例的 PASS 替代；尚未执行 |
| **C. 端到端科学收益** | 真实实验、时间切分/前瞻验证或可检查的独立科学任务，与明确基线比较 | 科研发现价值、候选独特性、可检验性和真实收益 | 不是“模型Judge说有信心”即可成立；尚未执行 |

**数据集隔离：** A 可以公开给开发人员调试；B 应在收集后分开发/保留评估集，保留集不能用于 Prompt 调整；C 需单独预先注册问题、评价和失败条件。任何标签争议保留多专家意见，不能事后为了匹配模型输出改写“金标准”。具体样本量、效应量与阈值交 M20 决定。

## 2. A 层：可立即用于跨模块纸面/静态走查的样例

### S01｜Goal Ethics 必须先于 Generation

- **设置：** Brief `B-01` 含一个因安全原因未通过 Goal Ethics 的研究要求。`M01.prepare_goal` 已得到 GoalContext，但 `M02.screen_goal` 返回拒绝（另外单测其技术未知/失败）。
- **预期：** 不执行 `M01.generate_hypotheses`，Run 或任务记录保留拒绝/未完成理由；不能创建合法根候选。
- **失败信号：** M01 在检查结果前生成候选，或 M02 的 API 超时被当成“通过”。
- **责任：** M14a、M15a、M01、M02、M12。

### S02｜编辑 Brief 不会改变正在运行的科学问题

- **设置：** `Project P1` 的 `Brief B1` 发起 `Run R1`，随后用户编辑产生 `B2`，改变了疾病模型和实验条件。
- **预期：** R1 的 GoalContext、policy 和既有模型请求继续引用 B1；B2 仅在新 Run/新准备阶段生效。
- **失败信号：** 旧 Run 的生成、R1 检索或 Ranking 悄然读取 B2。
- **责任：** M14a、M15a、M12。

### S03｜R2 发现普通必要前提遗漏：走 R1 补核查，而非 R3

- **合成机制：** `H-RPE-1` 提出“干预 X 通过状态 Y 改善细胞表型 Z”；最初 Inventory 漏掉从状态 Y 到表型 Z 的必要因果桥接条件。
- **预期：** R2 提交作用域明确的 `R1SupplementRequest`；M03 补上必要前提，M04/M05 按需查证，M06 形成更新的 Dossier，回 R2 重新完整评议；**不因此触发 R3，不更改 H-RPE-1 科学原文，也不能提前 Admission**。
- **失败信号：** R2 直接宣布可准入；或者把普通 Coverage 缺口升级为高影响 R3；或者修改原假说冒充补 Claim。
- **责任：** M03–M07、M09、M12。

### S04｜高影响 R3 问题与重复 Issue

- **设置：** R2 识别假说核心前提可能在目标实验条件下方向相反，形成高影响 Issue `I-1`；R3 在设定范围内核验后报告“存在矛盾证据，科学结论仍需限制”。重复收到措辞不同但事实和范围相同的 `I-1`。
- **预期：** R3 结论回到 R2，R2 最终归纳；无实质新事实不得重复派发相同 Issue。若 R3 真实执行不完整，R2 不能将其标为科学上已经核验完成。
- **失败信号：** R3 直接准入；重复循环；把“未有新论文”当成“没有发现”或技术失败当成科学未知。
- **责任：** M07、M08、M12。

### S05｜无直接证据 ≠ 科学阻断或工作未完成

- **设置：** 假说 `H-NOVEL` 的必要 Claim 已按规定查询范围完成支持/反证/先前工作检索，取得材料亦完成评价；没有直接支持该新桥接的研究，但不存在已发现的阻断性反证，且可提出可检验预测。
- **预期：** M09 不**仅因为没有直接论文**机械拒绝；Admission 必须基于完整性、阻断性问题和可检验性实际判定。是否有足够比较覆盖是 M10 的独立问题。
- **失败信号：** `no_direct_evidence` 直接映射 `blocked`，或 Ranking 自动发起补文献任务。
- **责任：** M05–M10。

### S06｜同一候选跨 Match 的固定核心科学输入

- **设置：** 合成候选 A 的核心呈现有“支持 E1、重要反证 E2、缺口 G1、最终 R2 结论 F1”。在 `Match(A,B)`、`Match(A,C)` 各运行一次；第二场允许从同一冻结 Dossier 增补讨论 C 所需材料 E3。
- **预期：** A 的四项核心内容在两场比赛完全一致（同一冻结政策及候选级核心版本）；E3 清楚标成**增补材料**。针对性选择遵守对双方同类、对称的科学逻辑并保存选取理由、实际全文/摘要与 A/B 排列。
- **失败信号：** `Match(A,C)` 为支持 A 隐去 E2；两场对 A 生成不同“核心总结”；只给一侧选择支持材料；保存 Dossier ref 却丢失实际模型输入。
- **责任：** M09a、M10、M15a、M20a。

### S07｜`needs_more_evidence` 不写 TrueSkill 或发检索

- **设置：** 两个已准入候选的 Match 中 Judge 给出 `needs_more_evidence` 或 `inconclusive`；另测外部 API 报错。
- **预期：** 三种情形均不更新 μ/σ；只有前两种保留科学比较反馈，技术失败单独记录。无 M03–M08 任务被这些 Match 自动创建。
- **失败信号：** 默认视为平局并更新评分、自动重启 R1/R2、将 API 失败解释为科学证据不足。
- **责任：** M09a、M10、M12、M15a。

### S08｜多代候选只追加到同一个 Epoch

- **设置：** `Run R1` 下 G0 候选 A/B 已入场并参加 Match；G1 产生 C，完成独立 Ethics/R0/R1/R2 后入场。
- **预期：** R1 只有一个正常 Epoch，C 追加成员；A/B 的 Admission 引用、既有 Match 和评分应用事实不被重写或迁移。
- **失败信号：** 每代创建新 Epoch，C 加入导致 A/B 证据自动变化，旧 Match 被重新解释。
- **责任：** M09a、M10、M12、M15a。

### S09｜强 RevisionSuggestion 不赋予未准入候选父代资格

- **设置：** 候选 A 已准入且达到 M10 父代资格；B 未准入，但 R2 给出很有吸引力的修改建议；C 准入但比较覆盖未达到 M10 父代资格。
- **预期：** UCB 父代候选池只包含 A。M11 不得从 B 自动修复型 Mutation，也不得把 C 当作合格父代。
- **失败信号：** M11 绕过 M10 的 ParentEligibility 直接选 B/C。
- **责任：** M09a、M10、M11a、M12。

### S10｜子代改实验情境，不能机械继承父代证据解释

- **合成机制：** 父代 H1 在“细胞体系 A、刺激条件 S1”假设机制 X→Y；子代 H2 保留 X/Y 名称，但变为“细胞体系 B、刺激条件 S2”并加入变量 Z。
- **预期：** M11 给 DeltaProposal；M03 完成 H2 Inventory 后解析 retained/modified/new；M04 可以保留父代原始材料作参考，M05 必须独立判断该研究对 B/S2 是否适用；M07 独立进行完整 R2；H2 的 μ/σ 使用新先验及新比赛而非继承 H1。
- **失败信号：** 文本相同导致强行重用旧因果结论；父代 Rating 直接赋给 H2；M11 自称 ResolvedDelta 已经可靠。
- **责任：** M03、M04、M05、M07、M11a、M10。

### S11｜外部调用重试、回放与评分幂等

- **设置：** 一次 Match 的模型调用发送后超时、随后技术重试；某个合法 `decisive` 科学结果又因恢复/重放被处理两次。
- **预期：** 每次真实发送 Attempt 分别记录可能的消耗/未知；本地重放不新增费用；同一已确认 Match 最多一次 TrueSkill 更新。技术失败与科学无法判断分别呈现。
- **失败信号：** 重放时 μ 连续更新两次、未知账单填 0、恢复后把相同外部调用算作新科学 Match。
- **责任：** M10、M12、M15a。

### S12｜正式终局：最高合格 μ，而不是最高 UCB

- **设置：** 使用完全人为的评级状态：A `μ=31` 但未达终局资格，B `μ=29` 且终局合格，C `μ=27` 且合格但因 σ 较大有最高 UCB；第二子场景三者都不符合终局资格。
- **预期：** 第一子场景 Winner=B；第二子场景 `NO_QUALIFIED_WINNER`（示例语义，非冻结枚举）。均不触发终局 R3。
- **失败信号：** 直接选 A，按 UCB 选 C，或在没有合格候选时强选“当前最高 μ”。
- **责任：** M10、M12、M16。

### S13｜检索成功但无结果 ≠ 检索技术失败

- **设置：** 查询 Q1 在报告的数据库及时间范围内返回 0 条；Q2 因 API 失败没有完成；Q3 返回论文元数据但全文不可获取。
- **预期：** 分别记录 `searched_empty_within_scope`、`failed/incomplete`、`metadata_or_abstract_only` 等不同语义；M05 不得在未读全文情况下推断全文方法学已经核查。
- **失败信号：** 统一标“无证据”，或者 Q2 触发“假说被证伪”。
- **责任：** M04、M05、M15a。

### S14｜A/B 顺序与材料偏差必须可检查

- **设置：** 同一个候选对分别以 A/B 和 B/A 排列，固定核心材料、相同补充规则，只有呈现顺序交换。
- **预期：** M10/M15 记录位置、输入和 Judge 决策；M20a 能识别是否存在位置偏差，不能把一次偏差性结果直接宣称科学改进。是否采用双向复评、如何统计由 M10/M20 决定。
- **失败信号：** 不保存排序信息；将一方论文篇数多直接作为支持度更高的科学依据。
- **责任：** M10、M15a、M20a。

## 3. B 层：需要真实文献和专家参与的医学科研案例类型

下表只指定**拟研究问题和应检验的推理能力**，不预设科学真值。真实材料需另行检索、下载、授权核查、定版和来源溯源；每一项均由专家独立标注后才能进入正式科学评测。

| 拟议主题 | 科学问题示例 | 主要评价维度 | 可能的困难 |
|---|---|---|---|
| RGC 亚型易损性 | 不同 RGC 亚型对代谢应激的易感性是否可能存在可检验的机制差异？ | 隐含前提、机制桥接、R2整体可检验性 | 亚型定义、跨模型外推、机制与相关性混淆 |
| RPE 氧化损伤与屏障 | 某候选通路能否解释氧化损伤后 RPE 屏障功能差异？ | 多终点解释、反证、材料适用性 | 细胞存活与屏障指标不等同；实验条件不同 |
| 青光眼神经保护 | 某种神经保护效应是否真的通过指定中间通路产生？ | 因果方向、竞争机制、预测可证伪性 | 结构与功能指标的时间顺序 |
| 角膜损伤修复 | 炎症调控与再上皮化之间是否存在机制上的必要桥接？ | Claim Coverage、混杂因素、体系依赖 | 创伤模型与临床情境不一致 |
| 遗传性眼病多因素机制 | 两个分子因子是否存在足以形成新机制的交互？ | Prior-art、组合新颖性、子代 Delta | 已知两个因子不意味着已知它们的联合机制 |

**建议保留至少一种“证据完整但科学上仍未知”的创新型候选**，以及一种“文献数量多但实际共享同一原始数据”的反例，避免评测系统性奖励保守或重复机制。是否构成科学上“高影响风险”需专家标注，而非仅凭文字激烈程度判定。

## 4. 专家科学案例的最小标注卡（设计草案）

只需一张可读记录，不建设独立标注平台。每张卡至少说明：

1. **任务与情境：** Goal、物种/疾病/细胞体系/实验情境，候选科学内容版本。
2. **可访问材料：** 固定的来源记录、论文类型、摘要/全文/补充材料实际范围、不能取得的部分；不伪造参考文献。
3. **关键 Claim 与因果链：** 必要/隐含前提及其相互依赖，专家无法确定的细节也要记录。
4. **Observed Finding vs Interpretation：** 研究真正报告了什么；哪些是模型或专家推论；适用性和偏倚风险。
5. **科学反馈：** 支持、反证、冲突、机制级遗漏、竞争解释；何种结论只有更深入核查才可能改变。
6. **预期输出：** 哪种模块行为属于合理判断；何种内容必须拒绝臆测、允许 abstain/未决；专家理由和不同意见。
7. **审计条件：** 被测模型实际使用的材料、Policy/Prompt版本、资源消耗、有没有在训练/开发见过该病例。

不要仅记录 `correct=true/false`；需要知道错误发生在检索遗漏、文献误读、因果外推、机制评价还是排序呈现。专家意见不一致时可保留多标签和争议理由。
